Intermediate — Locator Practice

Attribute substrings, parent/ancestor axes, and positional predicates. Write a CSS selector and/or XPath and click Check.

Section 1 — Self Details

Beyond exact matches: target attributes by substring — contains, starts-with, or ends-with.

Use these when IDs or hrefs are partially dynamic (e.g. user-42-name where 42 changes) but share a stable prefix or suffix.

CSS uses [attr*=] [attr^=] [attr$=]. XPath uses contains() and starts-with() functions. XPath has no native ends-with in XPath 1.0 — use substring() instead.

Section 2 — Relations

Go beyond forward traversal: use general siblings in CSS, and the parent:: and ancestor:: axes in XPath to navigate upward through the DOM.

Use ancestor:: when a wrapper container changes dynamically (e.g. modal opens) but the inner element stays stable — anchor to the stable inner element and climb up.

CSS has no upward traversal. parent:: and ancestor:: are XPath-only. When CSS cannot express the selector, only the XPath input appears.

Introduction to XPath Axes

XPath provides multiple axes for navigating the DOM.

The following-sibling axis selects later siblings.

The preceding-sibling axis selects earlier siblings.

CSS Selector
XPath
CSS ~ is the general sibling combinator — selects all later siblings that match, not just the immediate one. XPath: following-sibling::p does the same.
CSS:  h3 ~ p
XPath: //h3/following-sibling::p

Section 3 — Index / Position

More powerful positional selectors: second-to-last, ranges using position(), and pattern-based odd/even rows.

Use position range (position()>1) to skip table headers in Selenium/Playwright when scraping data rows.

position()>n is XPath-only — CSS has no range predicate. Some Relations use position too (e.g. :first-child); the difference is Index targets by count within a matched set while Relations navigates tree structure.

Section 4 — Visual Relations

Find elements by what's visually near them: an error message next to a field, an input under a section heading, or a checkbox inside a card.

These patterns are common in real-world test automation where dynamic IDs exist but visible structure is consistent across builds.

XPath text() matching (e.g. //h2[text()="Shipping"]) lets you anchor to visible headings that appear in the DOM — a powerful technique when structural attributes are unreliable.

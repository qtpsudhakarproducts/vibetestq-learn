Section 1 — Self Details

Self Details selectors target an element using its own attributes — id, class, type, name — without involving any other element in the DOM.

Use these when the element has a stable, unique identifier. They are the fastest and most reliable locators in Playwright and Selenium.

Both CSS and XPath support all self-detail attributes equally. Prefer id or data-testid over class when possible — classes change with styling refactors.

Section 2 — Relations

Relation selectors navigate the DOM by describing how an element relates to others — parent, child, sibling, or ancestor.

Use these when an element has no unique own attributes but has a consistent structural position relative to a known element.

CSS can select descendants, children, and following siblings. XPath can also go upward (parent, ancestor) and backward (preceding-sibling) — see the Index and Advanced sections. See also → Index section for positional navigation.

Section 3 — Index / Position

Positional selectors target elements by their order among siblings — first, last, or a specific nth occurrence.

Use when you need to pick a specific card, row, or item by its position when no unique attribute exists.

Testing caution: Positional selectors break when new elements are inserted. Prefer stable attributes whenever possible. Use index selectors only when order is guaranteed by the application design. Note: Index differs from Relations — Relations navigates the tree; Index picks by count within a matched set.

Section 4 — Visual Relations

Visual relation selectors find an element by its visible context — nearby label text, containing section name, or link text — rather than invisible technical attributes.

Use these when an element has no unique id/class but has a consistent visible label or heading near it on screen.

CSS can target by structural adjacency (label+input). XPath adds text() and normalize-space() to match by actual visible words. XPath text matching is particularly powerful for button and link text.
Exercise 11 Beginner

Expected: 1 element
Live HTML — Sandbox
CSS Selector
XPath
CSS: the label's for attribute links to the input's id — use label[for="b11-email"] + input. XPath: text()="Email" matches by visible label words then following-sibling::input[1] finds the next input.
CSS:  label[for="b11-email"] + input
XPath: //label[text()="Email"]/following-sibling::input[1]

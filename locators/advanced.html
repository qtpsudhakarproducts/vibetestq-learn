Advanced — Locator Practice

Multi-predicate logic, compound CSS, XPath functions, and DOM-scoped queries. Write selectors and click Check.

Section 1 — Self Details

Combine multiple attribute predicates on a single element using AND logic in both CSS and XPath, and use NOT to exclude elements.

CSS chaining (input[type="text"][name="q"]) is implicit AND. XPath uses multiple predicates: [...][...] or explicit and within a single predicate. CSS :not() and XPath not() handle negation.
Exercise 27Advanced

CSS Selector
XPath
CSS: chain multiple [attr=val] on the same selector — no space between them. XPath: use and inside a single predicate: [@a="x" and @b="y"].
CSS:  tr[data-role="editor"][data-status="active"]
XPath: //tr[@data-role="editor" and @data-status="active"]

Section 2 — Relations

Deep tree navigation: use preceding-sibling, combine ancestor + descendant in one expression, and select multiple axes in a single XPath.

preceding-sibling:: goes backward through siblings — useful for tables where a cell's sibling is the label column. //ancestor::div//following-sibling::span chains multiple axes in one path.
Exercise 30Advanced

XPath
Start from the status <td> that contains the Active chip. Then use /preceding-sibling::td[last()] — in preceding-sibling, [last()] is the furthest left sibling (first in DOM order), which is the Name cell.
XPath: //td[.//span[contains(@class,"chip-active")]]/preceding-sibling::td[last()]

Section 3 — Index / Position

Complex positional logic: select a specific row in a filtered subset, pick a cell by column index, and combine position with attribute predicates.

When XPath evaluates //tr[@data-status="active"][2] — the [2] applies AFTER the attribute filter, so it picks the 2nd active row. Order matters: //tr[2][@data-status="active"] means "only if row 2 is active" — a different question entirely.

Section 4 — Visual Relations

Match elements by partial text (contains(text(),...)), find a row by a cell's visible content, and navigate from a heading text to a sibling input in deeply nested structures.

contains(text(),"partial") is one of the most-used patterns in real-world test automation because labels often change in exact wording but keep key words stable. Always prefer it over text()="exact" for resilience.
Exercise 34Advanced
Partial Text Match — contains(text())
Four buttons are shown. Select all buttons whose visible text contains "Submit" — there are 2 (one says "Submit Form", one says "Submit & Continue").
Expected: 2 elements
Live HTML — Sandbox
CSS N/A — CSS cannot match by visible text content.
XPath
contains(text(),"Submit") matches any button whose text node includes "Submit" anywhere. Note the difference from text()="Submit" which requires an exact match.
XPath: //button[contains(text(),"Submit")]

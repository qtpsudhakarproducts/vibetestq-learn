Tricky Elements

The Hover Element Problem

The Problem:

  • Hover over menu ? Submenu appears
  • Move mouse to DevTools ? Submenu disappears!
  • How do we inspect it? ??

4 Solutions:

1 setTimeout + debugger

2 Breakpoint on Subtree

3 Force Element State

4 Console Override

Solution 1: setTimeout + debugger

// In Console, type:
setTimeout(() => { debugger; }, 5000);

// Press Enter ? You have 5 seconds!
Enter command
Hover element (5s)
?? Freezes!
Inspect calmly

Adjust timing: Change 5000 to 3000 (3s) or 7000 (7s)

While Paused:

  • Element stays visible in Elements tab
  • Inspect submenu items
  • Press F8 to resume

Solution 2: Breakpoint on Subtree

Steps:

  • 1 Find parent element in Elements tab
  • 2 Right-click ? "Break on" ? "Subtree modifications"
  • 3 Blue breakpoint icon appears
  • 4 Hover over menu
  • 5 ?? Pauses when submenu added to DOM!
Before hover:
<div class="dropdown">
</div>
After hover (paused):
<div class="dropdown">
  <ul class="submenu"> ? Just added!
    <li>Item 1</li>
  </ul>
</div>

Solution 3: Force Element State

For CSS hover effects (no JavaScript)

  • 1 Select element in Elements tab
  • 2 Styles panel ? Click ":hov" button
  • 3 Check :hover
  • 4 Element shows hover state!

Available States:

  • :hover
  • :active
  • :focus
  • :visited
  • :focus-within

?? Limitation:

Only works for pure CSS hover effects, not JavaScript-triggered elements

Solution 4: Console Override

// 1. Find element selector
const tooltip = document.querySelector('.tooltip');

// 2. Force it visible
tooltip.style.display = 'block';
tooltip.style.visibility = 'visible';
tooltip.style.opacity = '1';

// 3. Now stays visible! Inspect in Elements tab

When to Use:

  • Quick hack for stubborn elements
  • Element controlled by JavaScript
  • Other methods didn't work

Shadow DOM - Console Access

// Get shadow root
const host = document.querySelector('custom-element');
const shadow = host.shadowRoot;

// Query inside shadow
const button = shadow.querySelector('button');
console.log(button);

// See entire shadow HTML
console.log(shadow.innerHTML);

Make it Inspectable:

temp1 = document.querySelector('custom-element').shadowRoot;
// Now can access temp1 in Console

Console Power - Testing Selectors

$() - CSS

Single element

$$() - CSS

All elements

$x() - XPath

XPath query

These shortcuts only work in DevTools Console!

$() - querySelector

// By ID
$('#username')

// By Class
$('.btn-primary')

// By Attribute
$('[data-testid="submit"]')

// Complex
$('form#login button[type="submit"]')

// Returns: <element> or null

Test & Highlight:

const elem = $('#login-btn');
elem.style.border = '3px solid red';

$$() - querySelectorAll

// Find all buttons
$$('button') // Returns: Array [button, button...]
$$('button').length // Output: 5
$$('button').map(btn => btn.textContent)
// Output: ['Login', 'Sign Up', 'Cancel']

Check Uniqueness:

const count = $$('.btn-primary').length;
if (count === 1) {
  console.log('? Unique selector!');
} else {
  console.log(`?? ${count} matches`);
}

$x() - XPath Testing

// By ID
$x("//*[@id='username']")

// By Text
$x("//button[text()='Submit']")

// Contains text
$x("//div[contains(text(),'Welcome')]")

// Parent navigation
$x("//input[@id='email']/..")

// Complex
$x("//div[@class='card']//button")

// Returns: Array of elements

Special Console Variables

Variable What It Is Example

$1 Previously selected $1.textContent
$2, $3, $4 Further back in history $2.click()
$_ Previous result $_ * 2

Workflow:

// 2. Switch to Console

$0.style.border = '2px solid red' // Highlight

What Can & Cannot Be Inspected

? Can Be Inspected:

  • Visible elements - Use Pick Locator ??
  • Hidden elements - Use DevTools search (Ctrl+F)
  • IFrame elements - Switch context or right-click inside
  • Shadow DOM (open) - Expand #shadow-root
  • Hover elements - Use setTimeout + debugger
  • Dynamic elements - Pause then inspect

? Cannot Be Inspected:

  • Not yet loaded - Wait for element to appear first
  • Closed Shadow DOM - No access even with tools
  • Elements removed from DOM - Gone is gone
  • Future states - Can't inspect what doesn't exist
  • Cross-origin iframes - Security restriction

Important Notes:

  • Pick Locator only works on elements you can click/see
  • Explore Panel tests locator code (not direct inspection)
  • first(), last(), nth() are code operations, not inspection methods
  • filter() is for refining code, not for inspecting elements

Best Practices

Common Mistakes to Avoid

? Mistake 1: Wrong Context

Element in iframe!

Fix: Switch iframe context first

? Mistake 2: Not Checking Uniqueness

Using first element only

Fix: Check $$().length

? Mistake 3: Stale Element

Page re-rendered (React)

Fix: Query fresh each time

? Mistake 4: Class vs Attribute

[class='btn'] won't match class="btn primary"

Fix: Use .btn or [class*='btn']

Selenium Reality

Playwright Built-in

Runner, Assertions, Fixtures, Parallelism, Reporting, Mocking, Tracing.

2. DX: UI Mode & Codegen

UI Mode: Interactive

Visual interface to watch tests run, inspect step-by-step, and explore DOM snapshots instantly.

Codegen: Auto-Generate

Record while you interact. Generates clean, resilient test code in real-time as you click around the app.

VS Code Plugin: Deep integration for one-click debug & locator picking.

3. Architecture: The BiDi Revolution

Selenium: Transitioning

Adding BiDi support (W3C standard) to its legacy "Classic" HTTP model. Retrofitting observability onto a 20-year-old core.

Playwright: BiDi-First

Architected for bidirectional events (CDP/BiDi) from day one. Features like auto-waiting are native, not added layers.

The Difference: While both now support BiDi, Playwright’s core logic is built around it, leading to higher execution stability.

4. Zero-Flake Design

Smart Auto-Waiting

Automatically waits for elements to be Visible, Stable, and Actionable.

No more Thread.sleep(). Clean data = better AI learning.

5. Browser Context Isolation

1 Browser = Many Isolated Contexts

  • Separate cookies, storage, and cache per test.
  • Ultra-fast parallelism (milliseconds to spawn).
  • Low memory usage compared to Selenium's browser-per-test.

Ideal for AI agents running in massive parallel.

6. API + UI Hybrid Testing

Skip UI bottlenecks for non-target scenarios.

  • Authenticate via API tokens once.
  • Inject storage state directly into browser.
  • Seed test data via direct requests.

8. Trace Viewer: Time Travel

A Trace is a full recording of a test run—clicks, network, and DOM snapshots.

CI Observability

Failed tests on CI generate a .zip trace. Replay the failure locally exactly as it happened.

Copy as Prompt

Generate an "AI Prompt" directly from the failure to get instant debugging help from LLMs.

"Every test explains itself, locally or in CI."

The Three Pillars of AI Testing

1. Planner Agent

Analyzes requirements or user stories to decide WHAT to test and plots the navigational path.

2. Generator Agent

Utilizes Codegen and MCP to write the actual test code using semantic, resilient locators.

3. Healer Agent

Uses Trace Data and DOM snapshots to automatically fix broken tests when the UI changes.

Playwright provides the Observability (Traces) and Control (MCP) that these agents need to function.

Q1.2

Why do we need Node.js?

Without Node.js ✗
  • ✗Cannot read / write files
  • ✗Cannot launch browsers
  • ✗Cannot run in terminal
  • ✗Cannot install packages
  • ✗Cannot run in CI/CD
With Node.js ✅
  • ✅Read/write files (reports, screenshots)
  • ✅Launch browsers (Chrome, Firefox, WebKit)
  • ✅Run from the terminal
  • ✅Install packages via npm
  • ✅Run in CI/CD pipelines
💡 Node.js (2009) — Ryan Dahl took V8 from Chrome and wrapped it with OS access. Without Node.js, Playwright cannot run.
Q1.3

How was JavaScript executed before Node.js?

Before 2009, JavaScript ran only inside web browsers. When a page loaded a <script> tag, the browser's JS engine executed it — and nothing more.

browser-only world (before 2009)
<!-- JS only ran inside this HTML page --> <script> // Could manipulate the page... but nothing else function validate() { return document.getElementById('email').value !== ''; } // ✗ Cannot read files, launch browsers, or run from terminal </script>
What JS Could NOT Do
  • ✗Access the file system
  • ✗Launch a browser (it was inside one)
  • ✗Run from a terminal
  • ✗Install packages
So teams used...
  • ☕Java + Selenium
  • 🐍Python + Selenium
  • 🔷C# + NUnit

Languages that could access files, launch processes, and run from the command line.

Q1.4

What is the difference between a browser JS engine and Node.js?

Both use V8 to run JavaScript. But their purpose and capabilities are very different.

Capability 🌐 Browser JS 🖥️ Node.js
PurposeMake web pages interactiveTest automation, servers, CLIs
DOM access✅ Yes✗ No web page
File system✗ No✅ Yes (fs, path)
Run from terminal✗ No✅ node script.js
window / document✅ Yes✗ No
Install packages✗ No✅ npm install
Run in CI/CD✗ No✅ Yes
💡 Your Playwright test code runs in Node.js, not in the browser. Node.js instructs Playwright to control the browser — your test itself never runs inside it.
Q1.5

What is ECMAScript and how is it linked with JavaScript?

The Relationship
  • 📋ECMAScript = the official specification (rulebook)
  • 💻JavaScript = the implementation
  • 🏛️Standardised by TC39 committee
  • 📅Yearly releases since ES2015
💡 Interview Tip: "ES6 and ES2015 are the same version." ES6 was informal; ES2015 is official.
Key Versions for Automation
  • 📦ES5 (2009) — forEach, map, filter
  • 🚀ES6/ES2015 — let/const, Promises, classes
  • ⚡ES2017 — async/await ← game changer
  • 🔗ES2020 — optional chaining ?.

Q1.9

Why was JavaScript not the first choice for automation before 2017?

Before 2017, JS had callback hell — deeply nested callbacks that were unreadable and hard to debug.

❌ Before async/await — callback hell
openBrowser(function(browser) { browser.navigateTo('login', function() { browser.fill('username', 'admin', function() { browser.click('submit', function() { // Done — buried 4 levels deep, unreadable }); }); }); });
2009
Node.js
JS escapes browser
2015
Promises
Cleaner, not sequential
2017
async/await
🎉 Game changer!
2020
Playwright
Modern automation
✅ With async/await — clean and sequential
test('login', async ({ page }) => { await page.goto('/login'); await page.fill('#username', 'admin'); await page.click('#submit'); await expect(page).toHaveURL('/dashboard'); });
Q1.10

What does "interpreted" mean? How does JavaScript execute code?

Compiled Language
  • 🔧Code converted to machine code before running
  • ✋Errors caught at compile time
  • ☕Examples: Java, C#
Interpreted (JavaScript)
  • ▶️Engine reads & runs source code directly
  • 💥Errors only appear at runtime
  • ⚡V8 uses JIT internally for speed
runtime typo — only crashes at line 50
// lines 1–49 run fine ... await loginPage.clikc(); // ❌ typo — crashes here at runtime // TypeScript catches this BEFORE any browser opens: // ❌ Property 'clikc' does not exist on type 'LoginPage'
💡 This is why Playwright recommends TypeScript — it adds a compile step that catches typos before any test runs.
Q1.11

What is the difference between JavaScript and TypeScript?

JavaScript
  • 🔀Dynamically typed
  • 💥Errors found at runtime
  • 🚀No compile step needed
  • 👍Quick scripts, small projects
TypeScript
  • 📋Statically typed — declare types
  • ✅Errors found before running
  • 🔍Full IDE autocomplete
  • 🏆Playwright's recommendation
💡 TypeScript is a superset of JavaScript. At runtime, TypeScript types are stripped — Node.js only ever sees plain JavaScript.

What is the difference between npm, npx, and yarn?

npm

Q1.14

What are semicolons in JavaScript and do you need them?

Semicolons are technically optional due to Automatic Semicolon Insertion (ASI) — the engine adds them in most cases.

⚠️ ASI has edge cases — always use semicolons in professional projects. ESLint enforces this with the semi rule.
ASI edge case bug
// ❌ ASI fails — reads as one statement let a = 1 (function() { console.log(a) })() // TypeError: 1 is not a function // ✅ Semicolons make it safe let a = 1; (function() { console.log(a) })();
Q1.15

What is strict mode in JavaScript?

What it prevents
  • ✗Silent global variables (x = 10 without declaration)
  • ✗Duplicate parameter names
  • ✗Writing to read-only properties silently
Auto-enabled by
  • 📦ES Modules — any file using import/export
  • 🔷TypeScript with "strict": true in tsconfig
  • 🎭All Playwright TypeScript projects
"use strict" example
"use strict"; x = 10; // ❌ ReferenceError: x is not defined let x = 10; // ✅ correct

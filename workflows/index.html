QA Workflows for the AI SDLC

A practical implementation guide for teams moving from ad-hoc AI assistance to explicit, governed QA workflows. Start with the repo foundations, route by SDLC type, then implement the workflow that hurts most on your project right now.

Start with Foundations Route by SDLC Type

Implementation Order

The shortest route to a working system is linear. Skip the foundations and the rest turns into prompt theater.

  1. 01
    Build the project repository Store requirements, scenarios, tests, decisions, and evidence where AI can query them.
  2. 02
    Make traceability live Use graph.json as the dependency map between requirements, code, tests, and coverage.
  3. 03
    Pick one workflow Choose the workflow that removes the most friction first, not the flashiest one.
  4. 04
    Add governance after traction Measurement and anti-pattern detection matter once multiple workflows are actually running.

How to use this guide
Read the foundations in order. Use the SDLC matching section to avoid overreaching. Then implement a single workflow, prove it on a real project, and add governance only after three or four workflows are alive.
